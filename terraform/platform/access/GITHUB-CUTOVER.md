# GitHub cutover checklist

## Uploaded and verified

The six `proxmox-{dev,prod,platform}-{plan,apply}` environments have their scoped
Proxmox API token, endpoint and URL. Dev/prod apply environments also have scoped
Ansible inventory credentials and the Cloudflare token. Dev and prod apply
environments use distinct Ansible SSH keys, matching their public keys under
`ssh/public_keys/ENVIRONMENT/ansible-ci.pub`; follow the
[SSH cutover procedure](../../../ssh/README.md#rotation) when rotating keys.
All apply environments have the replacement
`TF_PLAN_PRIVATE_KEY`. The repository's `TF_PLAN_PUBLIC_KEY` was updated, as was
the legacy `proxmox-rw` private key so existing main-branch workflows remain
compatible. The actual saved-plan encryption scripts passed a round-trip test.

The existing apply environments require the reviewer (`rauland`) and allow only
`main`. Prod planning also requires review because its Proxmox token can change
disks.
The shared repository-level WireGuard secrets are inherited.

All six environments also have their scoped `AWS_ACCESS_KEY_ID` and
`AWS_SECRET_ACCESS_KEY`. The credential identities, policy boundaries and live
S3 read isolation were verified before upload. The state-access Terraform plan
reported no changes.

The temporary readiness flag and its workflow checks have been removed.

## Automatic dev apply setup

Before pushing the workflow change, create `proxmox-dev-auto-apply` without
required reviewers and restrict deployments to the branch `main`. Copy all 11
scoped secrets and the `AWS_DEFAULT_REGION` variable from `proxmox-dev-apply`.
GitHub cannot return secret values; use the existing protected local credential
sources and upload via stdin without printing credentials. Keep both dev
environments in sync when rotating credentials.

Terraform dev applies use this additional environment. The original
`proxmox-dev-apply` retains its reviewer for explicit destroy, state unlock and
standalone Ansible. Prod/platform approvals remain unchanged. Existing waiting
runs use the environment selected by their original workflow revision; a new
push generates fresh plans using the updated routing.

## Scoped AWS state access

Use the [state-access Terraform root](../state-access/README.md#optional-terraform-provisioning)
with a temporary administrator profile to provision the six scoped AWS users,
policies and access keys. The existing least-privilege CLI user does not need
IAM administration permissions. The same README includes an alternative
[IAM console checklist](../state-access/README.md#aws-console-setup) and six
exported policy files; import console-created resources before managing them
with Terraform.

Workflows now assume scoped IAM roles through GitHub OIDC using each
environment's `AWS_ROLE_ARN` variable; see
[GitHub OIDC roles](../state-access/README.md#github-oidc-roles). The access key
secrets remain only until that rollout is verified.
Keep administrator/broad state credentials out of the new environments.

Push the prepared workflow and directory changes before testing CI. After
verifying the state permissions, generate fresh plans and test the new workflows
using the scoped environment credentials.
Plans encrypted before the key rotation must be regenerated by rerunning all
jobs. Keep the replacement private-key backup secure.

## Delete only after successful cutover

Do not delete legacy secrets while remote workflows still use them. Once the
new workflows complete successfully:

| Location | Delete | Keep |
| --- | --- | --- |
| `proxmox-ro` environment | The entire environment, including its old AWS/Proxmox secret copies | Nothing, once no workflow references it |
| `proxmox-rw` environment | `PROXMOX_USER`, `PROXMOX_TOKEN_ID`, `PROXMOX_TOKEN_SECRET`, `PROXMOX_URL`, `TF_VAR_VIRTUAL_ENVIRONMENT_ENDPOINT`, `TF_VAR_VIRTUAL_ENVIRONMENT_API_TOKEN`, `PROXMOX_USER_ANSIBLE`, `PROXMOX_TOKEN_ID_ANSIBLE`, `PROXMOX_TOKEN_SECRET_ANSIBLE`, `SSH_PRIVATE_KEY_ANSIBLE`, `CLOUDFLARE_API_TOKEN`, `TF_PLAN_PRIVATE_KEY` | `AWS_ACCESS_KEY_ID` and `AWS_SECRET_ACCESS_KEY` are still used by the S3 Bootstrap workflow; retain the environment/reviewer protection |
| Repository secrets | `GMAIL` appears unused by the checked-in workflows; optional cleanup after confirming no other use | `PEER_IP`, `RUNNER_IP`, `WIREGUARD_ENDPOINT`, `WIREGUARD_PEER_PUBLIC_KEY`, `WIREGUARD_PRIVATE_KEY` |
| Repository variables | No deletion needed | `TF_CLI_ARGS_INIT`, `TF_PLAN_PUBLIC_KEY` |

Keep the new environment secrets and their `AWS_DEFAULT_REGION` variables.
Deleting GitHub secret copies does not revoke AWS or Proxmox credentials.
Retire old Proxmox CI tokens only after checking that no other automation uses
them. Keep the local `terraform@pve` administrator and the existing AWS CLI key
needed for platform administration/S3 bootstrap until separately replaced.
